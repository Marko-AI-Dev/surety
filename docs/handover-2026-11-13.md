# Handover: what changed on 13 Nov 2026

For anyone (person or agent) picking this repo up without the conversation that produced it. Read `AGENTS.md` first; this note is the history behind it.

## Decisions Marko made today

- **The buyer's screen is one chat with their agent.** Standard chat layout, built on shadcn/ui and Tailwind, keeping the glass look.
- **No countdown.** A negotiation ends when a committed quote meets the brief, when the buyer asks for what the agents have, or at the buyer's decide-by time (a backstop, up to 30 days).
- **Two negotiator modes** the buyer can switch at any time: full autonomy, or approve-first (every message to a supplier waits as a draft the buyer can reword, send or discard). The buyer can also write to a supplier directly.
- **One sentence is enough to start a purchase.** What matters most and how hard to push are assumed and shown as changeable.
- **Two interfaces:** the buyer's (friendly) and the admin's (also friendly, more technical and organised).
- **Design by playground first:** two or three clickable variations, approved before anything is built in the app.
- **His five yardsticks for every screen:** speed to the first "it's working" moment; the most care on onboarding; copy what works; cut what is barely used; never show a dead end.
- **How to work:** the principles in `AGENTS.md`, adopted today (rules file, one check command, test first, AI journey testing).
- The money still locks only on the buyer's yes. That did not change.

## How to see it without any secrets

```bash
PRACTICE_PORT=4227 pnpm practice
```

```bash
SURETY_API_URL=http://127.0.0.1:4227 API_TOKEN_VIEW=VVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVVV pnpm --filter @surety/web exec vite --port 5199 --strictPort
```

Then open `http://localhost:5199/#/`. The practice backend is the real API over an in-memory store with a scripted team: no keys, no ledger, no agents. Its ledger links are not real and its chat answers come from a stand-in.

## Not yet verified on the live backend

Everything from #15 onward has been run only on the practice backend and in unit tests. Before a live demo:

1. Apply the new migration and run `pnpm test:db` (the new SQL in `pg-sourcing-repo.ts` has only run against the memory store).
2. Merge into the live checkout, `pnpm install`, `pnpm paperclip:team` (the agents run from a copy), restart `pnpm suppliers`.
3. One full-autonomy run and one approve-first run from `#/`. Watch that the Lead recommends as soon as `decideNow.ready` is true, that a supplier commits when asked for its final committed quote on the quote form, and that the negotiator copes with a held draft.
4. Ask the chat a question and check the answer against the record.
