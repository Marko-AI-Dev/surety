## Recommendation

policy-v1 does not fit the train split (see the threshold check). Thresholds may change only in a new version that still approves no bad training file; a policy that has to approve a bad file to pass a good one is refused, and those good files stay held for review.

policy-v2: added after this run because the train split showed honest work escalated under policy-v1 (good/long-summary 0.75, good/lowercase-descriptions 0.77) while no bad file scored above 0.04 for satisfaction. Chosen on train only: the approve satisfaction drops from 0.90 to 0.70, the vendor's starting yes threshold, leaving a wide margin above every bad score. The injection gate (approve at most 0.10, decline at 0.50) and the decline satisfaction (0.10) are unchanged, so no bad training file is approved. good/empty-summary (0.11) stays escalated: going lower would mean approving on a score that says probably not, which is lowering a threshold to rescue a result. Holdout check: no holdout file falls in the 0.70 to 0.90 band, so the holdout confirms v2 approves no bad file but cannot confirm the new band itself.

Active policy for new jobs: policy-v2. Caveat: 20 examples on one synthetic invoice measure separation on this workload only; they are not a calibration claim for other invoices or tasks.
