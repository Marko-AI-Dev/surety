## Recommendation

policy-v1 does not fit the train split (see the threshold check). Thresholds may change only in a new version that still approves no bad training file; a policy that has to approve a bad file to pass a good one is refused, and those good files stay held for review.

policy-v2: added after the first run (evidence/jev-calibration-2026-11-08T22-49-07-738Z.json) because its train split showed honest work escalated under policy-v1 (good/long-summary 0.75, good/lowercase-descriptions 0.77) while no bad file scored above 0.04 for satisfaction. Chosen on train only: the approve satisfaction drops from 0.90 to 0.70, the vendor's starting yes threshold, leaving a wide margin above every bad score. The injection gate (approve at most 0.10, decline at 0.50) and the decline satisfaction (0.10) are unchanged, so no bad training file is approved. good/empty-summary (0.11) stays escalated: going lower would mean approving on a score that says probably not, which is lowering a threshold to rescue a result. The first run (20 files) had no holdout file in the 0.70 to 0.90 band, so the holdout gained four honest-but-awkward and four false-but-polite probes aimed at it and the set was rerun live. Kept after the rerun: no bad file is approved in either split, the band holds 2 good and 0 bad holdout files and v2 approves both, and the false-but-polite probes scored 0.01 to 0.02, far below the band. One honest probe (good/awkward-mixed-case, 0.41) stays escalated under both policies, which refunds and is safe. Scores drift between runs by up to 0.05 (good/long-summary 0.75, then 0.70, exactly on the v2 boundary), so honest work near 0.70 can land either side; the safety margin is the gap to the bad files.

Active policy for new jobs: policy-v2. Caveat: 28 examples on one synthetic invoice measure separation on this workload only; they are not a calibration claim for other invoices or tasks.
